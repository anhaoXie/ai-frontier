# AI 前沿日报

这个技能负责**把候选清单变成有判断的报告**。

## 先搞清楚职责边界

系统里有两个不同的东西，别混：

| | 图形界面（`启动AI前沿雷达.cmd`） | 这个技能 |
|---|---|---|
| 采集 | ✅ 按钮「获取今天信息」 | 可代跑 |
| 查看清单 / Excel | ✅ 按钮 | 可代开 |
| 生成报告 | ✅ 但**只是本地筛选整理** | ✅ 联网搜证 + 领域判断 |
| 联网核实 | ❌ 做不到 | ✅ 核心价值 |
| 判断重要性 | ❌ 做不到 | ✅ 核心价值 |

界面上的「生成报告」按钮产出的是**数据摘要**（`src/local_report.py`）：
按用户选的条数/主题/分数下限做切片，逐条列出标题摘要热度链接。
它明确不联网、不判断重要性 —— 报告开头就印了这句话。

**这个技能要产出的是另一种东西**：读懂了再写，并注明哪些核实过、
哪些是推测、哪些还没确认。两者不能互相替代，不要用摘要冒充分析。

**如果用户刚在界面上点过「获取今天信息」，数据就是新的，不要重复采集**
（浪费时间，还可能因为源抖动拿到更差的结果）。

## 采集实现说明

编排逻辑在 `src/pipeline_run.py`，命令行和图形界面都调它。
所以真正的失败处理只有一处，修的时候不会漏掉另一条路径
（这个坑本项目踩过一次：arXiv 静默返回 0 条的判断只补在了一条路径上）。

## 流程

### 第 1 步：跑采集（若当天数据不存在或已过期）

先看 `ai-frontier/out/candidates/<今天>.json` 是否存在且日期是今天。
不存在就采集。采集器需要这些参数：

- `<PYTHON>`：用 `load_workspace_dependencies` 拿到的 python 路径
- 工作目录：`ai-frontier`
- 命令：`<PYTHON> src/collect.py`

采集耗时约 45 秒，其中网络占绝大部分，用后台任务跑。
失败一两个源是正常的（有的站点本机访问不到），**不要因为个别源失败就重跑**。

### 第 2 步：读候选清单

读 `ai-frontier/out/candidates/latest.json`。结构：

```
totals            本轮口径：原始/过滤后/去重后/最终候选数
source_diagnostics 每个源抓了多少、是否有产出（这里的 ❌ 要写进报告）
candidates[]      候选条目，按 score 降序
  title/url/body     标题/链接/正文（arXiv 是摘要，博客是全文）
  score              0-100，本轮相对分位（最高分=100）
  topics[]           主题标签
  sources[]          哪些源报道了它
  corroboration      有几个【互相独立】的来源团体报道（常为 1，这是正常的）
  cross_group        有几个渠道收录（如 arXiv + HF Daily = 2）
  metrics            热度原始数据（points/stars/upvotes/downloads）
  extra.components   分数明细（显著性/热度/源权重/新鲜度/首次出现/独立印证）
  extra.salience_hits 命中了哪些信号词
```

**不要全读。** 候选 120 条，正文很长。策略：

1. 只读 `candidates[:35]`，`body` 截断到 400 字
2. 从里面选 **8-15 条**写进报告。选的标准见下面「什么是重要的」
3. 用 `grep` 按主题标签捞补充条目，而不是通读全部

### 第 3 步：联网核实头部条目

对选出的前 5-8 条，用 `web_search` 查一下。**这一步不能省**，
因为采集器只有标题和摘要，而"这条到底是不是真的、有没有被夸大的"只有搜索能回答。

搜索时注意：

- 论文就搜标题 + "paper"，看有没有讨论、有没有被质疑
- 产品发布就搜名字 + "release / announcement"，确认是否真发布、有没有后续
- 结果与候选清单冲突时，**以你搜到的为准**，并在报告里注明分歧

### 第 4 步：写报告

写到 `ai-frontier/out/reports/<YYYY-MM-DD>.md`。结构：

```markdown
# AI 前沿日报 · <日期>

> 覆盖窗口 / 采集源数 / 候选数 / 一句话总览

## 今日要点（3-5 条）
每条一句话，按重要性排序。这是给只读 30 秒的人看的。

## 一、头条：<最重要的一件事>
### 事实        只写能核实的
### 为什么重要   对做 AI 的人的具体影响，不要空话
### 不确定的地方 有什么还没确认、可能反转

## 二、论文精选（3-6 篇）
每篇：标题 / 链接 / 一句话讲了什么 / 值得读的理由

## 三、开源与产品动向

## 四、值得注意的观点

## 五、数据质量说明
- 哪些源今天没跑出来（从 source_diagnostics 里读）
- 本轮哪些判断是推测
- 候选总数与最终入选数的差距说明什么
```

### 第 5 步：转成 Word / PDF

用采集器自带的渲染器（它封装了 DSH 自带的 LibreOffice）：

```
<PYTHON> src/make_docx.py out/reports/<日期>.md --pdf
```

环境变量 `AF_LO_NODE` / `AF_LO_CLI` 可覆盖 LibreOffice 路径；
不设就用本机默认值。转换失败就只交 Markdown，并说明原因，
**不要去找系统装的 soffice**。

### 第 6 步：交付

- Markdown 日报：`out/reports/<日期>.md`
- Word / PDF：同目录
- Excel 候选清单：`out/candidates/<日期>.xlsx`（采集器已生成，直接交付）

## 什么是重要的

采集器的分数**已经**算进去了这些，但你需要用领域判断复核：

**该写进报告的：**

- 一线实验室发新模型/新能力（OpenAI/Anthropic/DeepMind/Meta）
- 开源权重模型发布，且不是量化再打包（采集器已过滤 gguf/awq）
- 改变做法的技术：推理效率的实质突破、新训练范式、Agent 能力的跨越
- 高 star 增速的新工具，且解决的问题是真实的
- 有数据支撑的反直觉结论（尤其是"大家以为 X，实测是 Y"）
- 监管/算力/供应链的实质变化

**不该写进报告的（哪怕分数高）：**

- 又一篇 benchmark 刷分论文，没有新方法
- 融资新闻，除非金额或收购方改变竞争格局
- 教程、观点合集、"N 个技巧"
- 量化/微调再打包的模型（同一模型的搬运）
- 企业 PR 稿（OpenAI RSS 里有大量客户案例）

**一个可操作的自检：** 读完这条，一个做 AI 的人明天的工作会不会有任何不同？
不会不同，就不写。

## 硬规则

1. **不许编。** 论文的结论只能来自摘要或你搜到的内容。没读到就说"未核实"。
2. **区分事实与推测。** 推测必须显式标注"这是推测"。
3. **来源体检必须写进报告。** 今天哪些源没跑出来要说清楚 ——
   源会悄悄死掉而不报错，沉默的失败比明显的失败危险。
4. **不要把分数当结论。** 分数是排序工具。可以在报告里引用它，
   但"分数高"本身不是"重要"的理由。
5. **报告要能只读 30 秒。** 「今日要点」放最前面，且每条能独立看懂。
